Cost Report: 2026-07-06-18-24-02

Executive Summary

This was an expensive run in walltime and inference volume: 18.37 hours elapsed, 65.89 summed agent-hours were recorded across branch and steered rows, and the five sessions consumed 2.684B tokens. GPU work and scheduler contention drove walltime; a dollar estimate is intentionally unavailable because the recorded gpt-5.6-sol model has no public list rate that can be applied responsibly.

The run was productive against its narrow dense n=512 target—the best kernel was 3.47× faster than the first full-valid port of the supplied baseline—but it did not beat the run’s 1234.320 µs full-suite geomean baseline. This is a single experiment, so the report does not imply cross-run cost variance.

Key takeaways

  • The fleet spent 17.29 completed GPU-hours executing and 28.29 aggregate agent-hours waiting for scheduler locks; waiting consumed 50.9% of the three worker sessions’ summed walltime.
  • Cache reuse was exceptional: 2.663B cached-input tokens were 99.21% of total tokens, while uncached input was 19.5M.
  • The three long workers consumed 777.1M–826.2M tokens each; none was a 2× cost outlier.
  • Nineteen context compactions occurred: seven, six, and five in the workers plus one in the manager.
  • Completed GPU calls stayed within the environment budgets; the longest recorded run was 346 seconds versus the documented 480-second benchmark and 600-second long-profile allowances.

Cost-Optimization Opportunities

  • Reduce GPU queue depth. Three benchmark-heavy workers on one B200 spent 22.87 aggregate hours waiting for gpu-0; one GPU-active worker with two research/edit workers would preserve concurrency without tripling queue pressure.
  • Preserve the current context-cache behavior. A 99.21% cache-hit share is excellent and offsets the very large cumulative context volume.
  • Bound shared worker-session growth. Nineteen compactions and 1.72M output tokens suggest that per-brief handoff summaries could reduce output and compaction overhead without giving up cache reuse.
  • Add native Codex custom_tool_call parsing and multi-brief session attribution to autocuda report data cost; manual reconstruction should not be necessary.
  • Record an explicit model pricing identifier if future deployments expose a billable public rate. This run cannot support a defensible USD estimate.

Analysis

The cost shape is dominated by a deliberately saturated one-GPU pipeline. Completed exclusive work occupied 94.1% of physical elapsed time, while the three workers simultaneously accumulated 28.29 wait-hours. That kept the device productive but inflated agent walltime and context growth: the fleet spent roughly half its combined worker-session time waiting for a scheduler gate.

Inference use was large but balanced. Workers A, B, and C consumed 792.6M, 826.2M, and 777.1M total tokens respectively, so no branch ran away relative to its peers. Nearly all input was served from cache; the actionable inference signal is therefore the 19 compactions and 1.72M output tokens, not cache misses.

Against the targeted dense n=512 case, the spend bought a reduction from 53.733 ms for the first full-valid supplied-kernel port to 15.474 ms, a 3.47× speedup. Against the run-wide geomean baseline, however, the best reported 1419.742 µs remained about 15.0% slower than 1234.320 µs. The value judgment is consequently target-dependent: strong for the requested megakernel case, not a general-suite win.

Recommendations: Run only one GPU-owning worker on single-device nodes, assign parallel workers to offline design and code preparation, start fresh worker rollouts at natural brief boundaries when compaction pressure rises, and preserve the high cache-hit workflow. Add billing metadata before using this report for financial planning.
