Root Causes

Ephemeral cache paths were treated as durable session capabilities. The skill catalog embedded a concrete plugin-cache directory in each session’s initial developer message. The plugin was reinstalled during this long run under a cache-busted directory, removing the old path without refreshing existing conversations. This is why the same deterministic read failed repeatedly rather than a worker-specific setup problem. Recovery was safe but wasted turns and made the newly fixed skill text unavailable until each worker searched manually.

The old continuation prose and CLI lifecycle were out of sync. The 0.4.0 explore-brief/SKILL.md says the manager can push a worker back into a stopped brief and that the worker should log a fresh start, but its only entry command is autocuda init brief. The CLI deliberately rejects a branch with a matching brief_stop. The current build’s autocuda resume brief is the correct fix, confirming that the three manual-reopen incidents were contract defects rather than expected kernel experimentation.

Plugin-root references were written as skill-local references. references/profilers.md lives beside skills/ at the plugin root, yet several skills name it without the required ../../ traversal. Under the skill-loading contract, relative resources resolve from the selected SKILL.md directory, so the manager’s failed skills/optimize-tree/references/profilers.md lookup was the specified behavior.

The report scanner does not cover the current Codex record shape. In lib/_report.py, _iter_codex_payload_texts accepts function_call_output and tool_result but not custom_tool_call_output; consequently 11 records containing invalid choice, unrecognized arguments, or missing required arguments never reached _skill_issue_signals_from_text. _EXPLICIT_SKILL_ISSUE_RE recognizes “bug/broken/wrong/incorrect/inconsistent/contradictory” but not the observed “conflicts”, “stale”, or “rotated”. Conversely, _has_autocuda_context treats any /autocuda/ worktree path as proof that a traceback is from autocuda itself, so normal submission failures become critical CLI incidents. Deduplication includes the source line, preserving the paired event and response copies of the same assistant text.

The six generated candidates were triaged as follows: bug_0000 and bug_0001 are NVRTC prototype build failures caused by unavailable math.h; bug_0002 is an intentional transpose-descriptor mismatch diagnostic; bug_0005 is an illegal GPU instruction from an experimental kernel during validation; and bug_0003/bug_0004 are the same sentence duplicated across Codex record views, where “instruction/layout boundary” refers to GPU instructions rather than skill instructions. These are normal optimization outcomes, not skill defects.

Fix Plan

  1. Make plugin skill locators stable across cache-busting installs. Update the catalog/plugin-cache resolver to expose a stable resource identifier or atomic current alias, retain an old cache directory while any session references it, and refresh active catalogs after installation. Test by starting a session, reinstalling the plugin under a cache-busted version, and reading the original skill locator successfully.
  2. Backport the current continuation lifecycle to every distributed explore-brief/SKILL.md: init brief for fresh/open briefs, resume brief after brief_stop, and no manual log ... start workaround. Add CLI lifecycle tests for fresh, crash-resume, stopped-resume, and double-resume rejection.
  3. Fix profiler links in skills/discover/SKILL.md, skills/optimize-simple/SKILL.md, skills/optimize-tree/SKILL.md, and skills/explore-brief/SKILL.md to resolve the plugin-root references/profilers.md. Add a packaging test that resolves every referenced local file from its containing SKILL.md.
  4. In lib/_report.py, add custom_tool_call_output to _iter_codex_payload_texts; recursively unwrap its array and JSON-wrapped output forms. Expand explicit-issue matching to conflict/stale/missing-path language, narrow autocuda_exception to known CLI frames, and deduplicate paired Codex message views by timestamp/category/normalized text. Regression fixtures should reproduce all six false candidates, the 11 missed CLI rejections, one stale path, and one resume conflict.
  5. Replace the autocuda status shorthand in skills/optimize-tree/SKILL.md with the complete accepted invocation and keep command examples synchronized with CLI --help in tests.
