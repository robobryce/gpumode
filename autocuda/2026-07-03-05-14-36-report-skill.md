## Root Causes

The implementation does not meet the harness coverage promised by `/home/shadeform/.codex/plugins/cache/brycelelbach-autocuda/autocuda/0.4.0/skills/report-skill/SKILL.md`, Procedure 2. In `/home/shadeform/.codex/plugins/cache/brycelelbach-autocuda/autocuda/0.4.0/lib/_report.py`, `_iter_codex_payload_texts` accepts `function_call_output` and `tool_result` but omits Codex `custom_tool_call_output`, which is where direct `functions.exec` results are stored.

The same module's `_skill_issue_signals_from_text` scans every overlapping window returned by `_local_text_windows`. Its local `seen` key includes the full window, so one traceback marker can produce many distinct rows from a single source record. This conflicts with the report contract's one-candidate-incident-per-row semantics. No `SKILL.md` command example is stale, and no setup prerequisite or confirmation-gate defect was confirmed.

## Fix Plan

1. Extend `_iter_codex_payload_texts` to treat `custom_tool_call_output` as `tool_result` context and recursively unwrap string, array, and JSON-encoded nested outputs. Add a fixture containing the four observed output shapes. Validate with `pytest -q tests/test_autocuda_reports.py -k 'report_skill_reads_codex_jsonl_payloads or custom_tool_call_output'`.
2. Deduplicate signals within one JSONL record by `(source line, context, category, signal)`, choosing the shortest useful evidence window, while preserving identical incidents on different records. Validate with `pytest -q tests/test_autocuda_reports.py -k 'report_skill_keeps_repeated_incidents or report_skill_deduplicates_multiline_record'`.
3. Re-run `autocuda report data skill` with the same 12 branch mappings and verify that the four CLI rejections appear once each, each multiline traceback appears once, and `autocuda schema check report-skill-csv --output 2026-07-03-05-14-36` still passes.
